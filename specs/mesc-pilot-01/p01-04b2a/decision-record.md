## PD-B2A-1 — Private module boundary

PENDING FOUNDER DECISION

Proposal:

- B2A remains private under `medscale.mesc`;
- no public facade or CLI;
- no mutation of the frozen B1 types defined in
  `src/medscale/mesc/split.py` and `src/medscale/mesc/_split_v1.py`;
- B2A types may wrap or reference B1 identities without changing B1
  serialization or behavior.

## PD-B2A-2 — Canonical value domain

PENDING FOUNDER DECISION

Proposal:

- fingerprinted promotable payloads permit only `null`, boolean, UTF-8
  string, unbounded integer, ordered array, and string-keyed object values;
- binary floating-point values are prohibited in fingerprinted promotable
  payloads;
- any ratio, threshold, or decimal quantity required later must use integer,
  versioned fixed-point, or canonical decimal-string representation frozen by
  contract;
- removes cross-runtime float-rendering ambiguity.

## PD-B2A-3 — Canonical JSON and JSONL

PENDING FOUNDER DECISION

Proposal:

- UTF-8; no BOM;
- recursive lexicographic key ordering;
- `ensure_ascii=False`; `allow_nan=False`;
- compact separators `(",", ":")`; no indentation;
- LF only;
- single JSON object ends in exactly one LF;
- JSONL contains one object per line, each ending in exactly one LF;
- no blank lines;
- zero JSONL records produce zero bytes;
- record order is supplied by the caller and must already be deterministic;
- serializers return bytes only and perform no filesystem I/O.

## PD-B2A-4 — Artifact descriptors

PENDING FOUNDER DECISION

Proposal:

- immutable descriptor containing `role`, `schema_version`, `sha256`,
  `byte_size`;
- `sha256` is exactly 64 lowercase hexadecimal characters;
- `byte_size` is a non-negative integer;
- descriptors are ordered canonically by artifact role;
- duplicate roles fail closed;
- missing required roles fail closed;
- unknown roles fail closed unless a new bundle schema version is ratified;

Required B2A artifact roles:

- `group_registry`
- `example_registry`
- `split_summary`
- `excluded_ledger`

Leakage reports are not part of B2A and must not be added to the required
role set.

## PD-B2A-5 — Non-circular fingerprint model

PENDING FOUNDER DECISION

Proposal:

- two-layer identity model: `SplitFingerprintIdentity` and
  `SplitFingerprintRecord`;
- `SplitFingerprintIdentity` contains bundle schema version, policy identifier,
  split algorithm version, split seed/domain separator, ordered artifact
  descriptors, and split-summary identity core;
- `SplitFingerprintIdentity` must not contain `split_fingerprint`, dates,
  timestamps, paths, usernames, hostnames, runtime versions, command logs, or
  environment data;
- `SplitFingerprintRecord` contains the complete identity payload and computed
  `split_fingerprint`;
- `split_fingerprint = SHA-256(canonical single-object JSON bytes of SplitFingerprintIdentity)`;
- the exact terminal LF generated by the canonical serializer is part of the
  hashed bytes;
- authoritative fingerprint is full 64-hex SHA-256;
- B1 16-hex `split_hash` remains display/compatibility-only and must not be
  used as B2A authority.

## PD-B2A-6 — Split-summary identity core

PENDING FOUNDER DECISION

Proposal:

`SplitSummaryIdentityCore` may contain only deterministic aggregate facts
needed to bind the split:

- total example count;
- total source-document/group count;
- partition totals;
- aggregate label totals;
- aggregate partition-by-label matrix;
- group counts by partition;
- excluded-record count;
- algorithm and schema identities when not already represented at the bundle
  level.

It must not contain per-example answer labels, raw question/context text,
dates or timestamps, the authoritative fingerprint itself, or runtime
provenance. D9 remains controlling.

## PD-B2A-7 — Fail-closed validation

PENDING FOUNDER DECISION

Proposal:

-introduced typed private validation errors for:

- `unsupported_value_type`
- `floating_point_value_prohibited`
- `non_string_object_key`
- `duplicate_artifact_role`
- `missing_artifact_role`
- `unknown_artifact_role`
- `invalid_sha256`
- `invalid_byte_size`
- `invalid_schema_version`
- `forbidden_runtime_metadata`
- `forbidden_date_or_timestamp`
- `fingerprint_mismatch`
- `canonicalization_failure`

CLI exit-code semantics are not reused inside the library.

## PD-B2A-8 — Determinism evidence

PENDING FOUNDER DECISION

Proposal:

future B2A acceptance requires:

- identical bytes on Python 3.11 and 3.12;
- identical golden-vector hashes on Windows, Linux, and macOS;
- locale-independent output;
- timezone-independent output;
- insertion-order-independent object serialization;
- Unicode preservation;
- deterministic rejection behavior.

Workflow or configuration changes are not automatically authorized by B2A.
Cross-platform evidence may be collected through existing infrastructure or
separately authorized validation infrastructure.
